## Modules — one row per document

Every module doc has the same shape: what it is, the files, how to run it, the routes or
verbs, the deviations from CONTRACTS.md, the known limitations, the tests.

| Document | Stage | Covers |
|---|---|---|
| [`modules/learner.md`](modules/learner.md) | 0 | The core: the append-only event store, the concept graph, the versioned item bank, the evidence rules, FSRS, misconceptions, disputes, holdouts, the two derived views, and the `learner` CLI |
| [`modules/learner-svc.md`](modules/learner-svc.md) | 1 | The same core over HTTP (`:5034`) and MCP (45 tools: 23 + 16 study + 6 exam-prep tools). Idempotency keys, `evaluation_method`, schema migration 1→2, and the Stage 2 read/log routes the gateway is built on |
| [`modules/teach-skill.md`](modules/teach-skill.md) | 0 | The pedagogy itself: `skills/teach/**`, the prompt pack, the rubric, prompt-pack versioning, and installing it into an agent host such as Claude Code |
| [`modules/telegram.md`](modules/telegram.md) | 1 | Optional Telegram reminders: a scheduled job (any scheduler), the push policy (retrieval, never content), how a tap becomes a recorded answer |
| [`modules/llm.md`](modules/llm.md) | 2 | Six providers behind one interface, the tutor/solver split that keeps evidence independent, structured generation with retries, the on-disk cache, and `LT_LLM_TIMEOUT_S` |
| [`modules/corpus.md`](modules/corpus.md) | 2 | The material: ingest, FTS5 + embeddings, page-level citations, cite-or-abstain, the three source roles, and treating source text as data rather than instructions |
| [`modules/tutor.md`](modules/tutor.md) | 2 | The line the project is built on: `orchestrator.py` decides, `generate.py` generates. Feasibility, hint legality, strategy rotation, the plan size guard |
| [`modules/gateway.md`](modules/gateway.md) | 2 | `:5033` — the phase machine, the answer keys that never leave the process, every `/api/...` route, the passport zip, and what is decided by code vs. generated by the model |
| [`modules/render-svc.md`](modules/render-svc.md) | 2 | The one Node container: Mermaid → SVG, Mermaid syntax check, KaTeX validation, and the write–render–look–fix loop |
| [`modules/web-ui.md`](modules/web-ui.md) | 2 | The browser surface: Next.js 15 against the gateway only, the graph view, evidence receipts, passport export |
| [`modules/study-tools.md`](modules/study-tools.md) | 2 | The model-free study tools (2026-09-24): question-bank import from markdown, practice graded server-side, blind-checking imported questions from an agent host, flashcards (self-rated, never evidence), comparison/definition tables, `PATCH` a goal's date and cadence |
| [`modules/exam-prep.md`](modules/exam-prep.md) | 2 | Exam prep on the study tools (2026-09-26): the goal's blueprint as data, new questions interleaved by blueprint share, per-day option shuffle graded by the order shown, sealed mock exams (pool `mock`), first-try progress by area with Wilson ranges |
| [`modules/sim-learner.md`](modules/sim-learner.md) | 1 | `scripts/sim_learner.py`: a truth-table scripted learner over a synthetic chain graph that runs two sessions against the learner core and reports the automatable gates — probe length session 1 vs 2, false-mastery rate, item rejection rate, holdout checks |

Stage 0 is the CLI plus the `teach` skill, and its gate is: actually learn something real,
measured on hidden delayed-transfer items. What ships in which stage, and the gate between
them, is [`../IDEA.md`](../IDEA.md) *Staging*.
